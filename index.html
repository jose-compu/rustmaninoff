Why not Checkov or Trivy

Those tools cover more. Rustmaninoff is the fast path when you already know the CKV ids you want to enforce.

Milliseconds, not seconds

54 ms on 1,540 resources vs 3.50 s Checkov (~65×) and 6.27 s Trivy (~116×). No Python VM and no policy-db refresh on the scan path.

One static binary

cargo install rustmaninoff, or a GitHub Release binary. Checkov needs Python and plugins. Trivy also pulls vulns, secrets, and SBOMs you may not want in an IaC-only job.

Checkov ids, Rust engine

Published CKV ids, YAML pass-conditions, and # checkov:skip= comments. Interpolations stay unknown and never fail CI. SARIF, JUnit, and JSON are first-class.

Install

cargo install rustmaninoff --locked
rustmaninoff scan . --framework terraform,cloudformation,kubernetes,docker

What it does

Terraform

.tf, .tf.json, and OpenTofu .tofu managed resources and data sources. Vars/locals via defaults, TF_VAR_*, and --var-file.

CloudFormation

YAML and JSON Resources. Attribute paths are relative to Properties.

Kubernetes

Multi-document YAML, including List. Inline skip via checkov.io/skip.

Dockerfiles

Dockerfile, Containerfile, *.dockerfile. FROM tag, USER, COPY vs ADD, HEALTHCHECK.

Speed, on one corpus

Wall-clock CLI time. Median of three runs after warmup (./scripts/bench.sh). 40 Terraform files (1,080 resources), 20 CloudFormation files (300 resources), 20 Kubernetes files (160 resources). Catalogs differ: Rustmaninoff 0.4.0 ran 536 built-in checks. Source: benchmarks/history.json.

Policy dialect

A check definition is the pass condition. Built-in YAML is rewritten from Checkov (Bridgecrew / Palo Alto Networks, Apache-2.0) and keeps published CKV ids.

metadata:
  id: CKV_AWS_3
  name: Ensure all data stored in the EBS is securely encrypted
  severity: HIGH
  framework: terraform
resource_types:
- aws_ebs_volume
definition:
  cond_type: attribute
  attribute: encrypted
  operator: equals
  value: true
